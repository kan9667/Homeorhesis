# SEH architecture

Use for architecture, ADR, contract, phase, ownership, and source-of-truth decisions.

1. Read `architecture.md` and relevant accepted ADRs.
2. Classify the decision by maturity label.
3. Resolve DSH versus SEH ownership before code design.
4. Map actors, authority, protected targets, evidence, failure posture, migration, rollback, and operator controls.
5. Preserve task-first selection, deterministic lane, provider/model openness, exact runtime qualification, one-GPU residency, child episodes, Web2 boundary, and independent gate.
6. Require an ADR for invariant or V1 contract changes.
