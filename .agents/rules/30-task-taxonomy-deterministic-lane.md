# Task taxonomy and deterministic lane

Classify immutable task objective, data class, tools, verifiers, modality, context, latency, and risk before model selection. Decompose only when bounded subtasks and evidence links improve control. Prefer deterministic code for parsing, hashing, schema validation, policy checks, exact transforms, replay, and other verifiable work. Derive a capability vector and required `ToolGrantManifest` before routing. A model never receives broader workspace, tool, data, export, or budget authority through decomposition or handoff.
